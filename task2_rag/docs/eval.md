# Task 2 评测报告

评测对象：RAG 写作系统全链路（`pipeline.py`，含真实 LLM 生成与引用校验）。
评测方法：3 个主题端到端运行（2 个语料内 + 1 个语料外），全部为真实一次性产物，落盘于 `eval/outputs/`，未做任何人工修改。

## 指标定义

| 指标 | 定义 | 达标线 |
|---|---|---|
| 引用覆盖率 | 文章中实际被引用的来源编号数 / 上下文提供的来源数 | ≥ 80% |
| 无据事实数 | 无 [Sn] 标记的公司事实句（人名/数字/案例），人工逐句核查 | 0 |
| 结构完整度 | 标题/导语/小标题/结语/参考来源 五要素齐全 | 5/5 |
| 幻觉拦截 | 语料外主题被拒答、假引用被降级 | 全部拦截 |

## 边界案例：拒答行为（主题 3）

「客户名单」「融资历史」均为 PDF 语料外信息。guard 双闸门的行为记录：

- 检索分数闸门**单独使用时确实被绕过**：公司名"万悉科技"在语料中高频出现，融合分 0.65 超过 0.35 阈值——这是实测发现的第一版设计缺陷；
- 主题词覆盖率闸门兜住了它：核心词（客户/名单/融资/历史）在语料中的真实覆盖 33% < 60% 阈值 → 拒答；
- 拒答输出结构化原因 + 缺口声明 + 3 个建议主题，明确声明"仅使用 PDF 内事实"——与 Trendee 反 AI 投毒、合规 GEO 的公开立场一致。

这个案例同时是设计文档与运行证据：说明为什么单一分数阈值不够、覆盖率闸门为什么排除实体词。

## 引用校验的实测拦截记录

| 拦截场景 | 触发方式 | 系统行为 |
|---|---|---|
| 越界引用 | 人工注入 `[S9]`（仅有 S1..S2） | 删除标记 + 告警"越界引用"（pytest 用例） |
| 编造内容引用 | 人工注入"Trendee 每年营收增长 300% [S1]"（S1 无此内容） | 词面重叠不足 → 降级删除（pytest 用例） |
| 宽泛引用 | 真实生成：结语句与 [S2] 来源重叠不足 | 自动降级删除 + demo/CLI 显示告警（端到端实测） |
| 语料外主题 | "客户名单和融资历史" | guard 拒答，未消耗任何 LLM 调用（端到端实测） |

## 已知局限

- 样本量小（3 主题），指标未覆盖 FAQ/品牌介绍等其余 genre 的生成质量
- "无据事实数"为人工逐句核查，未自动化（无据检测本身是 NLP 任务）
- 词面重叠校验是词袋近似：同义改写的编造（语义抄袭）拦截能力有限
