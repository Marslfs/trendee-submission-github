## 边界案例：拒答行为（主题 3）

「客户名单」「融资历史」均为 PDF 语料外信息。guard 三态闸门（normal / degrade / refuse）的行为记录：

- 检索分数闸门**单独使用时确实被绕过**：公司名"万悉科技"在语料中高频出现，融合分 0.65 超过 0.35 阈值——这是实测发现的第一版设计缺陷；
- 主题词覆盖率闸门兜住了它：核心词（客户/名单/融资/历史）在语料中的真实覆盖 33% < `DEGRADE_GATE` 0.40 → `refuse` 硬拒（0.40~0.60 区间是 `degrade`，会降级生成并在文首声明，而不是拒答）；
- 拒答输出结构化原因 + 缺口声明 + 3 个建议主题，明确声明"仅使用 PDF 内事实"——与 Trendee 反 AI 投毒、合规 GEO 的公开立场一致。

这个案例同时是设计文档与运行证据：说明为什么单一分数阈值不够、覆盖率闸门为什么排除实体词。

### 为什么选三态，而不是把阈值降到 0.40

0.40 确实能在这 14 条上做到 9/9、0/5，但那是**贴着测试集调参**——换一份语料，
「语料外主题」的覆盖率完全可能落到 0.40~0.55，届时就会误放并编造。
因此保留三个语义清晰的档位，让判定与阈值解耦：

```text
SCORE_GATE    = 0.35   # 不变
DEGRADE_GATE  = 0.40   # 新增：低于此值硬拒
COVERAGE_GATE = 0.60   # 不变：达到此值正常放行
# 无命中 / score < 0.35 / cov < 0.40   → refuse（硬拒）
# 0.40 <= cov < 0.60                   → degrade（放行但降级）
# cov >= 0.60 且 len(hits) >= 2         → normal
```

`degrade` 时 `pipeline.run()` 照常生成文章，但在开头插入显式声明
「本次检索只覆盖主题词 {cov:.0%}……未覆盖部分不作推断」，`app.py` 同步用 `st.warning` 展示；
`refuse` 行为不变。这样既不编造，也不把有证据的主题硬拒。

**修复后复跑**：`python scripts/scan_guard.py` → `14 主题，误拒 0 / 误放 0，判对 14/14`；
Task2 用例数由 11 增至 17（新增 3 条 A3 假 client 用例 + 3 条三态用例）。

## 已知局限

- 样本量小（3 主题），指标未覆盖 FAQ/品牌介绍等其余 genre 的生成质量
- "无据事实数"为人工逐句核查，未自动化（无据检测本身是 NLP 任务）
- 词面重叠校验是词袋近似：同义改写的编造（语义抄袭）拦截能力有限


## 检索质量量化（recall@5 / MRR@10 / nDCG@10）

此前只有定性描述「扩展/重排有用」，没有可复算指标。现以 36 条人工标注
（`eval/retrieval_eval.jsonl`：30 条主题 + 6 条口语/中英混写变体，标注单元为页、二值相关）跑三档配置，
`python scripts/eval_retrieval.py` 一条命令复算，结果落 `docs/retrieval_eval.md`：

| 配置（全部查询 n=36） | recall@5 | MRR@10 | nDCG@10 |
|---|---|---|---|
| BM25 原始 | 0.655 | 0.728 | 0.680 |
| BM25 + 术语扩展 | 0.623 | 0.684 | 0.637 |
| + 启发式 rerank | **0.698** | **0.834** | **0.742** |

如实说明（这也是标注的价值所在）：
- 术语扩展让**主题类**查询 recall@5 从 0.755 微降到 0.692——通用扩展词（优化/品牌）把长尾页拉进 top5；
  但它把**口语变体**的 recall@5 从 0.153 提到 0.278，变体上扩展是净收益。
- rerank 把 MRR 从 0.728 提到 0.834（主题类 0.803 → 0.898），靠标题命中奖励把正确页顶到第一位，是当前性价比最高的一步。
- 口语变体整体 recall@5 = 0.444，是主要短板；逐条命中见 `docs/retrieval_eval.md` 末尾表。
- 标注口径：单一标注者、依据页面标题与正文首段判定，无交叉校验，换人可能有 ±5% 波动；生产应双人标注 + Kappa。
