# Task 2 · 基于 RAG 的品牌内容写作系统

基于万悉科技品宣 PDF（36 页）构建的 RAG 写作系统：输入主题 → 检索资料 → 生成带页码级引用的官网 Blog / FAQ / 品牌介绍。**引用可溯源、幻觉可拦截、资料不足会拒答**。

> 快速开始：
>
> ```bash
> # 0) 一次性构建（改过 PDF 或参数时重跑）
> python -m src.parse && python -m src.clean && python -m src.chunk && python -m src.index
>
> # 1) CLI 跑全链路（检索→重排→上下文→闸门→生成→引用校验）
> python -m pipeline "为什么中国出海品牌需要进行 GEO 优化"
>
> # 2) Streamlit Demo
> streamlit run app.py
> ```
>
> 生成环节需要 `.env` 配置 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL（OpenAI 兼容接口，换供应商零改动）。**无 Key 时自动降级为离线模式**：输出检索证据包与构建好的 Prompt，链路其余环节照常可验。

## 一、架构

```mermaid
flowchart LR
    A[品宣 PDF 36 页] --> B[parse<br/>按页+字号解析<br/>block 级阅读顺序]
    B --> C[clean<br/>页眉页脚剔除<br/>断行合并]
    C --> D[chunk<br/>标题感知切分<br/>400/80]
    D --> E[index<br/>jieba 分词<br/>BM25Okapi]
    E --> F[(data/index/<br/>bm25.pkl)]
    F --> G[retrieve<br/>术语扩展<br/>多路归一融合]
    G --> H[rerank<br/>启发式 20→6<br/>LLM 重排留接口]
    H --> I[context<br/>[S1..S6] 编号<br/>预算句级截断]
    I --> J{guard<br/>分数+覆盖率<br>双闸门}
    J -->|资料不足| K[拒答<br/>结构化原因+缺口]
    J -->|放行| L[generate<br/>OpenAI 兼容<br/>DeepSeek]
    L --> M[cite_check<br/>句级引用校验<br/>越界删除/降级]
    M --> N[文章+引用卡片]
```

## 二、Chunk 策略

| 参数 | 值 | 依据 |
|---|---|---|
| size | 400 字符 | 偏小块利于精准命中；原料是 PPT，单页正文通常 1-2 块 |
| overlap | 80 字符 | 向前借整段补上下文，不切割句子 |
| 最小单元 | 段落 | 不按固定 512 字符硬切——硬切会把图表和它的表头切开，检索到半张表比检索不到更糟 |
| metadata | `page` / `section` / `chunk_id` | page 是引用溯源的最小单元；chunk_id = `p{页号:03d}-{序号}` 稳定可复现 |

**为什么不用向量检索（默认关闭，留接口）**：品宣语料充满专有名词与数字（"GEO""LLM 原生""65% 引用率"），BM25 精确匹配更稳；36 页规模毫秒级、零模型零下载。语义召回缺口由 retrieve.py 的术语扩展弥补；有 embedding 时可插入混合检索，架构不动。

## 三、Prompt 全文

### system（`prompts/system.md`）

```markdown
你是万悉科技（Trendee）官网的内容撰写专家，负责基于公司品宣资料撰写 Blog / FAQ / 品牌介绍。

## 铁律（违反任何一条即为不合格输出）

1. **只用资料内事实**：你的全部事实依据是用户消息中给出的编号片段 [S1]..[Sn]，来自品宣 PDF。禁止使用这些片段之外的任何公司事实、客户案例、数据指标、时间、人名。
2. **每个事实必须带引用**：凡是涉及公司事实/数据/案例的句子，句末必须标注来源编号，如 [S1] 或 [S1][S3]。通识性观点（如"AI 正在改变搜索"）可不标注。
3. **禁止编造引用**：只允许引用用户给出的编号，禁止出现 [S7]（若只有 6 个来源）等越界编号。
4. **资料不足即声明**：若片段不足以支撑某个小标题的论述，直接删掉该小标题，而不是用常识填充。整体证据不足时输出"资料不足"声明。
5. **语言**：简体中文，专业但克制的营销文风；不堆砌形容词，用 PDF 内的数据与案例说话。

## 输出结构（Markdown，固定）

# {文章标题}

{导语：2-3 句，点出主题与结论}

## {小标题 1}
{正文段落，事实句带 [Sn] 引用}

## {小标题 2}
...

## 结语
{总结 + 行动建议，不引入新事实}

---
**参考来源**
- [S1] 第 X 页 {小节名}
- [S2] ...
```

### user（`prompts/user.md`，`{context}` 处注入编号片段）

```markdown
请基于以下编号资料片段，撰写一篇官网 Blog。

**主题**：{topic}
**文章类型**：{genre}

## 资料片段（每段开头标注编号与页码，这是你唯一的事实来源）

{context}

## 写作要求

- 围绕主题组织 2-4 个小标题，每个小标题至少对应一个资料片段。
- 涉及公司事实、数据、案例的句子末尾标注 [Sn]。
- 不要出现资料片段之外的 Trendee 公司事实（人名、客户、数字一律以片段为准）。
- 严格按 system 中的输出结构输出，文末附"参考来源"列表。
```

## 四、幻觉控制与引用溯源（三层防线）

| 层 | 时机 | 机制 | 实测证据 |
|---|---|---|---|
| ① 生成前闸门 | 检索后、调用 LLM 前 | guard：融合分 < 0.35 或主题实词覆盖率 < 60% → 拒答。"客户名单/融资历史"类问题因公司名虚高命中会被分数闸门放过，覆盖率闸门（排除实体词+中文前 2 字近似匹配）兜住 | 「客户名单和融资历史」被拒，输出结构化原因+缺口声明 |
| ② 生成中约束 | Prompt | 铁律 1-4：只用资料内事实、每事实带 [Sn]、禁越界编号、不足即声明 | 2 篇真实生成文章引用规整、0 编造 |
| ③ 生成后校验 | 文章返回后 | cite_check：句级解析 [Sn]，越界编号删除+告警；词面重叠不足降级删除（逗号级切分避免同句连坐） | 自动拦截并降级了一处宽泛引用（结语 [S2] 与所在句重叠不足） |

## 七、已知局限

- 纯 BM25 检索：同义改写（非术语级）召回弱于向量方案；术语扩展表人工维护
- rerank 为启发式：无 cross-encoder 语义精排（LLM 重排接口已留，`--llm-rerank`）
- 语料仅 36 页品宣 PPT：guard 阈值（0.35/0.6）基于本语料实测标定，换语料需重标
- 清洗的页眉页脚判定基于重复率统计，本 PDF 无统一页眉页脚（实际剔除 0 行），对有页眉页脚的文档更有效
